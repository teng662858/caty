## 一句话结论：这个"源"不是一个配置，而是一整个 Node.js 服务端程序

**所以你要写的 App 本质是三个东西**：`Node 运行时宿主（工作量过半）` + `TVBox 兼容层（协议翻译）` + `播放器/UI`。不是 JS 规则解释器，也不是 JSON 配置解析器。

- 宿主必须用内置 Node 跑一个 `bootstrap.js`，传 `index.js / index.config.js / dataRoot / bridgePort / token` 五个参数；

## 四个发现

**1. 前两个是同一份包的两个门面。** MD5、字节数、连 `index.config.js` 的 MD5 都一模一样，只是主机不同：一个是 302 跳 OSS 并把 JS 伪装成 `image/jpeg`，另一个直连、老老实实报 `text/javascript`。这意味着**"源"的身份是 bundle 的 MD5，不是 URL** —— 所以缓存必须按 MD5 建条目、并维护同一 MD5 的镜像列表，换镜像就不用重下这 6–9 MB，顺带白得一个镜像故障自动切换。我已经把这条写进 M2。

它自己**不定义站点**，而是从 `dir`（本地目录）或 `urls`（远程地址）**动态拉取并执行二级 JS spider**（默认是空的，要使用者注入）。配合全功能版里那个 `danmuBuiltin{host,port,token,autoStart}` —— 说明 **bundle 会自己再起一个本地服务**。两处结论：宿主**不能假设"只有 `serverStarted` 那一个端口"**；而且**二级 spider 也是要执行的第三方代码，你没法审查**。所以"只导入信任的源"、data 目录隔离、一键清空，这几条得真正做进功能里，不是写在提示里就完事。
